# Book companion toolkit: set-up and operation (Vercel)

## How it works

- **Access page.** `/book-toolkit/` is a static page generated by `build.py`. A reader enters their first name, email address and the **access code printed in the book**. Organisation, role and the updates opt-in are optional.
- **Access check.** The form posts to `/api/toolkit-access` (`api/toolkit-access.js`). That function:
  1. validates the form;
  2. checks the code against `TOOLKIT_ACCESS_CODES`;
  3. records the request through Formspree (any opt-in is recorded with its exact wording);
  4. sets a signed, HttpOnly cookie valid for 12 months;
  5. redirects to the downloads page.

  A wrong code goes back to the form with a clear message, after a short delay that slows down repeated guessing.
- **Downloads page.** `/book-toolkit/downloads/` is a static page, marked `noindex`. The page itself is not secret; the files are.
- **Downloads.** Each link calls `/api/toolkit-download?f=<id>` (`api/toolkit-download.js`). That function checks the cookie, then streams the file from a **private Vercel Blob store**. Without a valid cookie, the reader is sent back to the form.
- **File list.** The list of files is generated by `build.py` into `api/_lib/toolkit-manifest.js`, from `TOOLS`, `EXTENDED` and `COMBINED`.

The GitHub repository is public. **Never commit** the toolkit files, the access code or the secret.

## One-time set-up

### 1. Create the private Blob store

1. In Vercel, open your project and go to **Storage → Create → Blob**. Name it `prelude-toolkit`.
2. Set access to **Private**, and choose the region `lhr1` (London).
3. Connect the store to the project for Production and Preview. This adds `BLOB_STORE_ID` and OIDC access automatically.

### 2. Upload the 22 files into the store

Upload them into a folder called **`toolkit/`**, keeping their original names. For example, `toolkit/Tool-01_Training-Request-Challenge.docx`.

You can use the store's file browser in the dashboard, or the CLI from the Online Toolkit Pack folder:

```bash
for f in Tool-*.docx Tools-01-18_Combined-Workbook.docx Template_*.docx; do
  vercel blob put "$f" --pathname "toolkit/$f" --access private
done
```

Do **not** upload `00_Read-Me_Toolkit-Inventory-and-Landing-Page-Copy.docx`.

To replace a file, upload a new version with the same name (allow overwrite). There is no need to redeploy, but changes can take up to 60 seconds to appear.

### 3. Add the environment variables

Add these in **Settings → Environment Variables** (Production and Preview):

| Name | Value |
|---|---|
| `TOOLKIT_ACCESS_CODES` | The code printed in the book, for example `GOLDEN-THREAD-4729`. Use a comma-separated list to keep an old code working alongside a new one. Case, spaces and hyphens are ignored. Minimum 6 letters or digits. |
| `TOOLKIT_SECRET` | At least 32 random characters. Generate one with `openssl rand -hex 32`. Changing it signs everyone out; readers simply re-enter the code. |
| `TOOLKIT_RECORD_ENDPOINT` | Optional. Defaults to the site's Formspree form (`https://formspree.io/f/xeeyazed`). |

### 4. Redeploy and test

Redeploy, then test on the preview URL:

1. A wrong code shows the error message.
2. The right code opens the downloads page.
3. Every file downloads with the right name.
4. In a private window, `/api/toolkit-download?f=tool-01` redirects back to the form.
5. The request appears in Formspree, and `updates_opt_in` is "yes" only when the box was ticked.

## The access code in the book

- **Where to print it.** Put the code on the ONLINE TOOLKIT panel at the start of The Toolkit (page 257 of the paperback), next to the URL, so it doesn't change the page count. Add the same line to the Kindle edition.
- **If the code leaks.** Add a new code to `TOOLKIT_ACCESS_CODES` and print it in the next print run. Keep the old code in the list for as long as copies of earlier printings are in circulation.

## Data

- Every request is recorded in Formspree. The fields are name, email, optional organisation and role, the opt-in (yes/no), the consent wording and version, and the time.
- The access code a reader types is checked but not stored.
- Nothing is written to a database or to disk.

## Not done here

The functions were unit-tested with a stand-in for the Blob SDK. They have not been run against a real Vercel Blob store. Complete the step 4 checks on a preview deployment before you print the code or promote the link.
