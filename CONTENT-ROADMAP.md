# Prelude Insights Hub — Content Roadmap

**Status: Built and live.** The Glossary and all 13 pillar clusters below have been built, verified and deployed, in the numeric order requested (0, then 1–13). Every item marked ✅ in this document now exists on the site. This file is kept as a record of the plan and the destination for each link — not as an outstanding to-do list. One deliberate deviation from the original plan: Cluster 6's proposed "What Is DSAT?" article was not written separately, since the existing DSAT Explained article (Cluster 9) already covers it fully — writing a second, near-identical piece would have been duplicate content. Cluster 6's pillar links to DSAT Explained directly instead.

**What this solved:** the brief asked for ~50 articles clustered around 13 topics, plus specifically asked for a proper "what is TNA, what is DSAT" information hub. This roadmap delivered both — a **Glossary** for fast, quotable definitions, and a **pillar-and-cluster structure** so the Insights Hub is a real resource rather than a flat list of blog posts.

---

## 0. The structural problem this fixes

Right now, `insights.html` is a flat grid of 9 article cards with no hierarchy. That works at 9 articles. It stops working at 50 — visitors (and AI crawlers) need a way to tell "the one page that explains everything about X" from "a specific angle on X." That's what pillar pages are for.

**The model:**
- **Glossary** — one hub page, ~25 short (2–4 sentence) definitions of the jargon Prelude's own site already uses (DSAT, TNA, JSP 822, Capability Framework, etc.), each linking out to the pillar page that covers it properly. This is the single highest-value page for AI search — "what is X" questions get answered directly and cited.
- **13 pillar pages** — one per cluster, each a comprehensive "everything you need to know about X" page. All 13 built.
- **~50 supporting articles** — narrower, more specific pieces that link back to their pillar and sideways to related articles. The 9 that existed before this roadmap slotted straight into the new structure without being rewritten; 44 new ones were written to fill it out.
- **Insights hub redesign** (still not built) — now that this much content exists, `insights.html` genuinely needs cluster-based organisation (like the sector filters already on `case-studies.html`), not a flat grid. This is the one item from this roadmap not yet actioned — see Section 5.

## 1. Glossary Hub — `glossary.html` (NEW)

One page. Terms grouped by cluster. Each entry: term, plain-English definition, link to the pillar/article that goes deeper. This directly answers your "what is TNA, what is DSAT" instruction — a visitor or an AI system can get the straight answer in one place, then click through for depth.

Proposed terms (all genuinely used elsewhere on the site already — nothing invented for this):

| Term | One-line definition anchor |
|---|---|
| DSAT | The Defence Systems Approach to Training — the JSP 822 methodology for designing, delivering and assuring Defence training |
| JSP 822 | The Ministry of Defence policy that sets out DSAT requirements |
| TNA (Training Needs Analysis) | The structured process of testing whether a performance gap is actually a training gap |
| Capability Framework | A defined, consistent standard of competence used for assessment, development and workforce planning |
| Capability Readiness Review™ | Prelude's ten-question diagnostic for finding which of six areas a performance problem actually sits in |
| Prelude Capability Model™ | The framework tracing performance from mission down to evidence |
| Capability Improvement Approach™ | Prelude's six-stage method: Mission, Gap, Root Cause, Intervention, Impact, Improve |
| Training vs Capability Decision Model™ | The test for whether a performance gap needs training or something structural |
| Capability Readiness Maturity Model™ | Five stages of organisational capability maturity, from Reactive to Optimised |
| Learning Governance | The decision rights and evidence trail behind how training is assured and audited |
| Training Governance | Governance specifically applied to training delivery and compliance |
| LMS (Learning Management System) | The platform used to deliver, track and report on training |
| Totara | An open-source LMS platform used widely across healthcare and public sector |
| Skills Framework | A map of the skills required for specific roles, distinct from a capability framework's broader standard |
| Workforce Planning | Aligning roles, skills and structure to operational demand |
| Learning Strategy | The document connecting capability investment to organisational goals |
| Digital Learning | Learning delivered through digital or blended formats, designed for adoption not just format |
| Performance Consulting | Diagnosing organisational performance problems before prescribing a solution |
| Organisational Development | The discipline of improving how an organisation functions structurally, not just individual skills |
| Change Management | Managing the human and structural side of organisational transformation |
| Succession Planning | Preparing the pipeline for critical roles before a vacancy forces a decision |
| Active SC / DV Clearance | UK Government security clearance levels (Security Check / Developed Vetting) |
| PRINCE2 | A structured project management methodology |
| CMI | Chartered Management Institute — UK leadership and management professional body |
| Apprenticeship Funding Compliance | The evidence and audit trail required to protect government-funded apprenticeship investment |

## 4. Build order — as actually run

The brief's final instruction was **"start at 0 and do numerically,"** which superseded the commercial-priority order originally suggested here. Actual build order: Glossary (0), then Clusters 1 through 13 in strict numeric sequence, one cluster per commit, each regenerated via `build.py`, diffed against the live site, browser-verified, then committed and deployed before starting the next.
